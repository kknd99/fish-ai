# 怎么写好 criteria（让 AI 推荐更准）

criteria 文件是 AI 判定的**唯一依据**。base_prompt 只负责"输出什么格式"，
criteria 负责"什么算好货、什么直接否决"。写得含糊，AI 就只能给你泛泛的评价。

## 一、你的现状：标准太薄

| 文件 | 字符数 | 参考范例 `macbook_criteria.txt` |
| --- | --- | --- |
| `iphone_air_criteria.txt` | ~491 | **4728** |
| `大石轮组_criteria.txt` | ~714 | |

这两个文件是「AI 生成任务」批量生成的，而生成时模型把一大半输出预算花在了思考上
（甚至把思考过程写进了文件），**正文被削掉了一半以上**。后果是 AI 的判定依据不足，
推荐偏"看着还行就推"，不够准。

## 二、好 criteria 的四段结构

照参考范例 `prompts/macbook_criteria.txt` 的骨架（它跑了很久、比较成熟）：

```
第一部分：核心分析原则（不可违背）
第二部分：详细分析指南
  A. 商品本身评估（各维度的 PASS / PARTIAL_PASS / FAIL 判定线）
  B. 卖家与市场评估（危险信号清单 + 豁免条款）
第三部分：输出格式（这一节在 base_prompt 里，不用你写）
```

**关键原则：写"可判定的规则"，不要写形容词。**

| ❌ 没用（AI 无法执行） | ✅ 有用（AI 能逐条对照） |
| --- | --- |
| 成色要好 | 有磕碰/划痕需在描述或图片中明确说明，否则判 FAIL |
| 价格要合理 | 高于同型号近期均价 15% 判 FAIL；低于均价 30% 且无合理解释，按可疑处理 |
| 卖家要靠谱 | 主页在售商品 > 20 件且品类杂乱，判为商家号，降级或 FAIL |
| 描述要详细 | 缺少「电池健康度」「是否拆修」任一关键信息，必须写入 `risk_tags` |

## 三、iPhone Air 草稿

把它保存成 `prompts/iphone_air_criteria.txt`（覆盖原文件前先备份）。

```text
[V6.4 逻辑修正] iPhone Air 二手交易判定标准

### 第一部分：核心分析原则（不可违背）

1.  **信息完整性优先**：判断"是否推荐"前，先检查关键信息是否齐全。关键信息缺失时，
    即使价格诱人也不能直接推荐，必须标记为"有条件推荐"并列出需要向卖家确认的项。
2.  **一票否决硬性原则（HARD DEAL-BREAKER RULES）**：以下任一项成立，
    `is_recommended` 必须立即为 `false`：
    - 存在 **ID 锁 / 网络锁** 未解除，或卖家回避"是否已退出 Apple ID"的问题；
    - 明确 **换过非原装屏 / 主板 / 摄像头**，且价格未体现（低于行情 30% 以上除外，
      但需在 `risk_tags` 标注"拆修机、价格异常"）；
    - 卖家描述中出现“代拍”“帮忙挂”“不议价勿扰”等**中介/商家话术**，且主页在售
      商品数量 > 20 件；
    - 要求**脱离平台交易**（加微信私下转账、先款后货、走“内部渠道”）。
3.  **价格锚定**：判价必须对比"同容量、同成色的近期成交/在售价"，而不是官方首发价。
    无法取得市场参照时，把 `price_confidence` 记为"低"，并降低推荐力度。

### 第二部分：详细分析指南

**A. 商品本身评估**

- `model_chip`：核对型号代次（iPhone Air 只有特定代次）、容量、颜色。标题与图片
  不符、或型号含糊（只写"iPhone Air"不写容量）判 PARTIAL_PASS。
- `battery_health`：**电池健康度是关键指标**。未提供 → FAIL 并写入 `risk_tags`；
  低于 85% → PARTIAL_PASS，需在理由中说明后续更换成本；低于 80% → FAIL。
- `condition`：外观需区分"轻微使用痕迹"与"磕碰/变形/进水"。卖家只写"成色好"而
  无实拍细节图 → PARTIAL_PASS。有进液、维修记录 → FAIL。
- `history`：**是否拆修**必须明确。只写"无拆修"而无购买凭证、保修状态、发票的
  交叉验证 → PARTIAL_PASS 并标记需确认。激活时间过近（< 7 天）且价格远低于
  官网 → 怀疑来路，标记可疑。
- `seller_type`：见下。

**B. 卖家与市场评估（核心）**

- 【首要结论】必须首先点明卖家画像：个人卖家 / 二手商家 / 疑似商家 / 无法判定。
- **危险信号清单（Red Flag List）及豁免条款**：
  - 主页在售商品数量多、品类杂（如同时卖手机、鞋、化妆品）→ 商家号，降级。
    *豁免*：若历史评价多为好评且价格仍显著低于行情，可判"有条件推荐"。
  - 注册时间短（< 30 天）或历史交易极少 → 风险升高，需在理由中点明。
  - 价格显著低于行情（> 30%）→ 优先怀疑：赃物、组装机、维修机。
    *豁免*：能提供购买凭证、发票，且可当面验机时，可降级为"有条件推荐"。
  - 描述里出现"急出""清仓""秒杀"等催促成交话术 → 标记 `risk_tags`，不作为
    单独否决理由，但需在理由中提醒。

**C. 我的偏好（按需修改这一段）**

- 优先考虑**可当面验机 / 同城自提**的商品。
- 只接受**国行**，港版/美版需在理由中明确提示（或直接判 FAIL —— 按你的取舍选一个）。
- 期望配置：<在这里写容量/颜色等硬性要求>。
- 心理价位：<在这里写你能接受的上限，超过即不推荐>。

**D. 推荐与否的判定**

- 全部维度 PASS 且价格合理 → `is_recommended = true`。
- 存在 1 个 PARTIAL_PASS 且其余 PASS → 可推荐，但理由必须写清"需向卖家确认什么"。
- 存在 2 个及以上 PARTIAL_PASS，或任一 FAIL → `is_recommended = false`。
```

## 四、大石轮组草稿

保存成 `prompts/大石轮组_criteria.txt`（先备份原文件）。

```text
[V6.4 逻辑修正] 大石(Dashi)碳纤维轮组 二手交易判定标准

### 第一部分：核心分析原则（不可违背）

1.  **规格先于成色**：轮组是"规格件"，装不上就是废铁。**开档、塔基、刹车接口**
    三项必须先确认；任一项缺失或与我的车不符，直接判 `is_recommended = false`
    并在理由中指出缺哪一项。
2.  **一票否决硬性原则（HARD DEAL-BREAKER RULES）**：
    - **开档不符**：我的车是 Boost（前 15×110 / 后 12×148）。标 100/142 快拆或
      QR 的，直接否决。
    - **塔基不符**：只接受 SRAM XD 或 Shimano MS/HG（按我的飞轮）。写成
      "其他塔基"、含糊不写、或不可更换的，直接否决。
    - **刹车接口不符**：只接受 6 孔或中锁（按我的碟片）——写成不匹配的直接否决。
    - **结构性损伤**：轮圈有裂、明显偏摆、辐条断裂或更换过、花鼓有异响/旷量 →
      直接否决（碳圈一旦结构受损不可修复）。
    - **来路不明**：只写"朋友的车拆下来的"、无购买记录、无原厂质保卡 → 降级为
      "有条件推荐"并要求提供购买凭证。
3.  **重量与框高要能被验证**：卖家声称的重量（如 1250g）若无称重图，标注为
    "卖家声称、未验证"，不据此加分。

### 第二部分：详细分析指南

**A. 商品本身评估**

- `model_chip`：核对品牌型号（大石/影豹、框高 40/50/60、轮径 29" 或 700C）。
    型号含糊（只说"碳轮"）判 PARTIAL_PASS。
- `battery_health`：轮组无电池，改判 **花鼓状态**：是否说明塔基类型、棘轮结构
    （如 36T/54T 棘轮）、轴承是否更换过。缺失 → PARTIAL_PASS。
- `condition`：区分"正常使用痕迹"与"摔车/磕碰"。有摔车史但已修复 → FAIL；
    仅有轻微擦伤且不影响结构 → PASS，理由中写明擦伤位置。
- `history`：是否含**内外胎/快拆/桶轴/胎垫/真空气嘴**。清单越完整越加分，但要
    区分"赠送"与"已含在价格里"。缺失关键配件（如桶轴）→ 需在理由中提示额外成本。
- `seller_type`：见下。

**B. 卖家与市场评估（核心）**

- 【首要结论】必须首先点明卖家画像：车友个人 / 车店或装车商 / 无法判定。
- **危险信号清单（Red Flag List）及豁免条款**：
  - 同一卖家在售**大量轮组/车架等配件** → 商家号，价格通常不占优，降级。
    *豁免*：车店清库存且提供质保，可视为加分项。
  - 描述里只有参数堆砌、没有任何实拍细节（花鼓、辐条、圈边、塔基）→ 要求补充，
    判 PARTIAL_PASS。
  - 价格显著低于同款行情（> 30%）→ 优先怀疑：翻新、修复、山寨（尤其"大石"有
    仿品）。*豁免*：能提供原厂购买记录/质保卡，且可当面验轮时降级为有条件推荐。
  - 要求"不退不换 + 先款后货"且不支持自提 → 标记 `risk_tags`。
- **市场参照**：用搜索结果里同框高/同品牌的在售价做区间判断，而不是凭印象。

**C. 我的偏好（按需修改这一段）**

- 硬性要求：**Boost 开档（110/148）+ XD 塔基 + 6 孔碟刹 + 29 吋**。
- 优先：带内外胎、可自提、有原厂质保卡。
- 接受：正常使用痕迹；不接受：摔车修复、偏摆、辐条更换。
- 心理价位：<在这里写上限>；框高偏好：<50 框高优先 / 不限>。

**D. 推荐与否的判定**

- 规格三项（开档/塔基/刹车）全部匹配 + 无结构损伤 + 价格合理 → `true`。
- 规格匹配但有一项信息缺失（如需确认塔基）→ 可 `true`，但理由必须写成
  "有条件推荐，需向卖家确认塔基规格"。
- 规格任一项不符或存在结构损伤 → `false`。
```

## 五、怎么用

**方式一（推荐）：替换文件内容**

```bash
cd /volume1/docker/xyfish/ai-goofish-monitor

# 先备份现有的
sudo cp prompts/iphone_air_criteria.txt prompts/iphone_air_criteria.txt.old
sudo cp prompts/大石轮组_criteria.txt prompts/大石轮组_criteria.txt.old

# 写入新内容（用 nano 粘贴，或从本文件复制）
sudo nano prompts/iphone_air_criteria.txt
```

**方式二：新建文件并在任务里指向它**

把草稿存成 `prompts/iphone_air_v2_criteria.txt`，然后在 Web UI 里编辑任务，
把「分析标准文件」改成新路径。

> ⚠️ 路径必须落在 `prompts/` 目录内（代码做了限制，防任意文件外带）

**改完不用重建容器** —— 爬虫每次运行都会重新读取 criteria ✓

## 六、自检清单

改完跑一次任务，对照检查：

- [ ] 启动日志里没有「分析标准过短」或「疑似混入思维链」的告警
- [ ] AI 判定结果里 `criteria_analysis` 各维度都有 `evidence`（而不是空话）
- [ ] 被否决的商品，理由里能看出**违反了哪一条硬性原则**
- [ ] 没有出现"全部推荐"或"全部否决"的极端情况 —— 那说明阈值定得不对
- [ ] 连续观察几天，推荐里真正值得看的比例是否提高

如果发现 AI 总是误判某一类，**不要调模型，改这一条规则**：把那条判据写得更具体、
更可判定，比换模型有效得多。
